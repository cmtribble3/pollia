Pollia Xcode workspace

Entry point: pollia.xcworkspace in the repository root.
The repository directory is already named pollia. CMake's project name and its
generated project directory are now pollia and pollia.xcodeproj. Mitsuba's
library, executable, and Python module names remain unchanged for API compatibility.

Regenerate from the repository root:
  ./generate-xcode-project.sh

The backend project and runtime live in
~/Library/Developer/Xcode/DerivedData/pollia-runtime by default. Set POLLIA_BUILD_DIR
to an absolute path before regenerating to override it. The source-only navigator
remains in build-pollia-xcode; old in-repository builds are preserved. The source navigator is generated
from real source files; edits in it modify the repository files directly.
Use Pollia Sources for everyday navigation. Keep Build collapsed unless
you need the full target/dependency tree. Generated build products and vendored
dependencies outside the selected Mitsuba/Dr.Jit sources are omitted from the
curated source navigator.

If Xcode asks to autocreate schemes, choose Manually Manage Schemes. The six
shared schemes generated by CMake are sufficient; leave Autocreate schemes off.

Schemes
  Pollia-Backend: builds the native executable, configured Python variants,
    dependencies and plugins; Run renders the RGB polarization smoke scene.
  Pollia-Metal-Smoke: builds the backend; Run executes the Python RGB smoke
    check with the dedicated interpreter and this build's Python bindings.
  mitsuba-bin: native executable and dependency build; Run uses RGB polarization.
  pollia_jarecki: plugin build; Run exercises it with stock RGB polarized transport.
  pollia_mueller: plugin build; Run exercises custom mono Mueller transport.
  pollia_pis: plugin build; Run exercises custom mono PIS transport.

Build Pollia-Backend once before using individual plugin schemes so the scenes'
other plugins and data are available. Run schemes default to RelWithDebInfo:
optimized native code with symbols. For performance comparisons, select Release
in Edit Scheme > Run > Info; Profile uses Release. Full Debug remains available
when optimization interferes with inspecting native variables. Different
configurations write to the same runtime locations: rebuild the selected
configuration before switching between them.

Native debugging
  Use mitsuba-bin or a plugin scheme with an LLDB debugger. Set breakpoints in
  Pollia Sources, e.g. src/mitsuba/mitsuba.cpp or a plugin constructor. GPU work
  is JIT compiled; a C++ breakpoint inspects host setup/tracing, not GPU lanes.
  Metal frame capture is enabled for these run schemes.

Python debugging
  Pollia-Metal-Smoke provides launch/environment setup and console output.
  A copy of the dedicated Python environment is staged in DerivedData for this
  launch; use the original .venv for package installation and regenerate after
  changing packages. Xcode's native debugger does not provide Python source-level stepping. Python
  source can be edited here, with Python debugging handled separately as needed.

Command-line build
  cmake --build "$HOME/Library/Developer/Xcode/DerivedData/pollia-runtime" --config RelWithDebInfo --target Pollia-Backend --parallel 8

Command-line environment and smoke check
  source scripts/pollia-env.sh
  python scripts/verify-metal.py --variant metal_rgb_polarized

The environment now selects the DerivedData runtime. To use the preserved older
runtime, set POLLIA_BUILD_DIR to the absolute path of build-make before sourcing.

Metal variants
  metal_rgb_polarized: forward RGB polarized rendering; no automatic differentiation
  metal_ad_mono_polarized: existing monochromatic polarized rendering
  scalar_rgb and scalar_mono_polarized remain compiled; all supplied run schemes
  explicitly select Metal. The verification script has no CPU fallback.
